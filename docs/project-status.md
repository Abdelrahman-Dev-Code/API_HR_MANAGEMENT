# حالة المشروع والفجوات المعروفة

## منفذ حاليًا

- Laravel 13 API.
- Sanctum Personal Access Token login/logout/me.
- صلاحيات Gates منفصلة للقراءة والإدارة، مع موافقات مستقلة للإجازات والرواتب.
- نطاق قراءة البيانات الشخصية حسب الدور: `hr_admin` لكل السجلات، و`department_manager` لقسمه، والموظف لسجلاته؛ كما تقيد عمليات الكتابة المرتبطة بموظف أو قسم بنفس النطاق.
- رموز Sanctum تنتهي افتراضيًا بعد 7 أيام، مع جدولة حذف الرموز المنتهية.
- CRUD API للموظفين والأقسام والوظائف والمستندات والعطل والحضور والإجازات وأرصدة الإجازات والرواتب والأدوار والصلاحيات.
- CRUD API للموظفين والأقسام والوظائف والمستندات والعطل والحضور والإجازات وأرصدة الإجازات والرواتب والأدوار والصلاحيات.
- واجهة React عربية وإنجليزية لإدارة الموارد البشرية، بما يشمل العطل الرسمية وأرصدة الإجازات، مع تصدير CSV لهذين الموردين.
- عملة المؤسسة قابلة للضبط من الإعدادات وتستخدم في عرض الرواتب، مع قيمة افتراضية `SAR`.
- API المؤسسة singleton للقراءة والتحديث؛ لا يوجد إنشاء/حذف عام للإعدادات.
- Repository Pattern عام وخاص لكل مورد.
- Form Requests للإنشاء والتحديث.
- API Resources للاستجابات.
- Models وعلاقات Eloquent وcasts.
- Factories و`HrSeeder`.
- Migrations منظمة في مجلدات فرعية ومسجلة في `AppServiceProvider`.
- دعم وردية `day` و`night` ووقت خروج يعبر منتصف الليل.
- API المؤسسة singleton عبر `GET/PATCH /api/organization`.
- Gate `manage-organization` وصلاحية `organization.manage` لمستخدم نشط ذي دور فعال.
- Workflow للإجازات: أيام العمل محسوبة بالخادم، منع التداخل، تحقق الرصيد، واعتماد ذري مع قفل.
- Workflow للرواتب: صافي محسوب بالخادم، اعتماد ودفع منفصلان مع سجل مستخدم/توقيت.
- ملفات المستندات تخزن على disk خاص وتنزل عبر Route محمي، والحذف soft-delete.
- مجموعة Postman لاختبار الصحة والمصادقة والقوائم ورسائل التحقق في `docs/postman/HR-Management.postman_collection.json`.
- الحضور يطابق وردية الموظف؛ DELETE للحضور غير متاح عبر API.
- المؤسسة تحتوي أوقات دوام منفصلة للنهار والليل.

## مطلوب قبل الإنتاج

### التفويض

عزل السجلات حسب الموظف والقسم منفذ. قبل الإنتاج، راجع صلاحيات الأدوار الفعلية، وعيّن دور `department_manager` مع ربط حساب كل مدير بملف موظف وقسمه الصحيح.

### سياسة الإجازات

اعتمدت المؤسسة استثناء العطل الرسمية من جميع أنواع الإجازات وعدم ترحيل الأرصدة بين السنوات. يحسب النظام أيام العمل ويقسم الطلب متعدد السنوات على أرصدة كل سنة، ولا يستهلك رصيد سنة أخرى عند نفاد الرصيد السنوي.

### سياسة الرواتب

حساب الصافي والاعتماد والدفع والتدقيق الأساسي منفذة. رمز العملة قابل للتغيير في إعدادات المؤسسة وقيمته الافتراضية `SAR`. العمل الإضافي يُدخل يدويًا مؤقتًا؛ ربطه بالحضور وقواعد الخصومات والتقريب ما زال يتطلب اعتمادًا منفصلًا.

### التاريخ والحذف

تستخدم بعض الجداول `cascade`، لذلك يجب اعتماد سياسة واضحة للحذف الفعلي. في نظام HR يفضل غالبًا الأرشفة أو soft delete للحفاظ على الحضور والرواتب والمستندات.

### الملفات

رفع الملفات الخاصة والتحقق والتنزيل المحمي منفذ. يلزم تحديد فترة الاحتفاظ وإجراء دوري لحذف الملفات المؤرشفة بعد انتهاء المدة المعتمدة.

### الاختبارات

تغطي Feature tests الحالية المصادقة، الصلاحيات ونطاق السجلات، رسائل التحقق، رفع المستندات، الورديات، الإجازات وأرصدتها، وسير الرواتب. آخر تحقق مركز للتغييرات: 50 اختبارًا ناجحًا. تشغيل المجموعة كاملة يحتاج إعادة تحقق بعد استقرار filesystem الخاص باختبارات المستندات.

قبل الإنتاج، وسّع اختبارات التكامل لبقية عمليات CRUD، وشغّل اختبارات التزامن على محرك قاعدة البيانات المستخدم في الإنتاج؛ اختبارات SQLite لا تحاكي أقفال الصفوف وسلوك التزامن في جميع المحركات.

## قرار التوسع إلى SaaS

المشروع مصمم حاليًا لشركة واحدة. عند التوسع:

1. أضف `companies`.
2. أضف `company_id` إلى الجداول التشغيلية.
3. طبّق global scope أو query scopes بحذر.
4. اجعل unique indexes مركبة مع `company_id`.
5. اربط User بالشركة أو جدول membership.
6. اختبر عزل بيانات شركة عن أخرى.
